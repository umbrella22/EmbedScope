EmbedScope 0.3.0 supports the published `rs_lvgl` and `rs_lvgl_ui` 0.5.0
native provider. The device wire protocol remains **v1**.

[Documentation](https://umbrella22.github.io/EmbedScope_website/)

## Native LVGL integration

- `escope-lvgl/native` uses `rs_lvgl_sys` 0.5.0 directly and shares the
  application's single native LVGL provider. The adapter does not require the
  higher-level Rust UI library or its layout configuration.
- Widget and layout classification continues to follow the application's
  effective native bindings, including configurations with Flex or Grid
  disabled. Native object identities, geometry, state and revision semantics
  retain the existing protocol contract.
- The native UI example covers the 0.5.0 typed constructors, `into_view()`,
  component slots, lazy `child_if` children and controlled `binding` updates.
  It checks the tree through the wire codec before and after native events,
  including a model-rejected slider value that reconciliation corrects.
- `App::overlay` mounts on LVGL's top layer, which is separate from the active
  screen. To inspect those overlays, integrations select the top layer as a
  `NativeTree` root. View keys and component names remain application-owned
  metadata; native inspection reports the resulting LVGL objects.

## Upgrade

| EmbedScope native SDK | Shared `rs_lvgl_sys` provider |
| --- | --- |
| 0.1.x | 0.3.x |
| 0.2.x | 0.4.x |
| 0.3.x | 0.5.x |

Upgrade the application and native adapter together. The default `escope-lvgl`
library and custom `TreeSource` implementations remain independent of LVGL.
Existing protocol-v1 devices can use this CLI and Inspector without a firmware
update. This release does not change the C ABI.

## Downloads

| Platform | Inspector | CLI |
| --- | --- | --- |
| macOS Apple Silicon | `embedscope-inspector-0.3.0-aarch64-apple-darwin.zip` | `escope-0.3.0-aarch64-apple-darwin.zip` |
| macOS Intel | `embedscope-inspector-0.3.0-x86_64-apple-darwin.zip` | `escope-0.3.0-x86_64-apple-darwin.zip` |
| Linux x64 | `embedscope-inspector-0.3.0-x86_64-unknown-linux-gnu.AppImage` | `escope-0.3.0-x86_64-unknown-linux-gnu.zip` |
| Windows x64 | `embedscope-inspector-0.3.0-x86_64-pc-windows-msvc.zip` | `escope-0.3.0-x86_64-pc-windows-msvc.zip` |

- **Inspector:** extract the macOS or Windows ZIP and launch the application.
  On Linux, run `chmod +x` on the AppImage and start it.
- **CLI:** extract the ZIP and run `escope --help` (`escope.exe` on Windows).
  Add its directory to `PATH` for use from any terminal. Rust is not required.
- **C/C++ SDK:** `embedscope-c-sdk-0.3.0.zip` contains `include/escope.h`,
  device SDK sources, a lockfile and a static-library wrapper. Build it for the
  firmware target and link the resulting library.
- **Rust SDKs:** `escope-protocol`, `escope-agent`, `escope-lvgl`, `escope-c-api`
  and `escope-host` are available on crates.io. Rust users can optionally install
  the CLI with `cargo install escope-cli --version '=0.3.0' --locked`.

`SHA256SUMS` covers the nine attached distribution archives. Rust crate archives
are distributed through crates.io.

macOS applications use ad hoc signatures and are not notarized. Linux requires
glibc 2.35 or newer, and Inspector requires a desktop OpenGL driver; the CLI
uses system `libudev`. AppImage extraction is available on systems without
FUSE. Windows executables use the static MSVC runtime.

The release workflow checks source archives, independent Rust and C consumers,
the real `rs_lvgl_ui` 0.5.0 memory display, CLI sessions and packaged Inspector
launches. The native UI consumer runs against extracted SDK archives before
publication and registry-only dependencies after publication, with exactly one
`rs_lvgl_sys` 0.5.0 provider in each dependency graph.
