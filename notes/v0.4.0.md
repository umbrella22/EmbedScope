EmbedScope 0.4.0 supports the published `rs_lvgl` and `rs_lvgl_ui` 0.6.0
native provider. The device wire protocol remains **v1** and the C ABI is unchanged.

[Documentation](https://umbrella22.github.io/EmbedScope_website/)

## Native LVGL integration

- `escope-lvgl/native` directly uses `rs_lvgl_sys` 0.6.0 and shares the
  application's single native provider. Widget and layout classification follow
  the effective application configuration, including disabled Flex or Grid.
- The UI constructors `container`, `progress_bar`, `message_box` and
  `animated_image` produce the native kinds `lv_obj`, `bar`, `msgbox` and
  `animimage`. Rust UI names do not rename protocol kinds, native C functions or
  Cargo widget features. Application semantic names, View keys and component
  boundaries can be supplied through a custom `TreeSource`.
- The native UI consumer checks the renamed constructors, `Style::plain`,
  separate Flex alignment controls, `thumb_style` and `progress_style`.
  It drives a real LVGL pointer through press/release, reconciles the queued
  application action and verifies changed RGB display pixels, stable geometry
  and rejected stale tree revisions. Existing composition, controlled-form and
  top-layer overlay checks also run.

## Upgrade

| EmbedScope native SDK | Shared `rs_lvgl_sys` provider |
| --- | --- |
| 0.1.x | 0.3.x |
| 0.2.x | 0.4.x |
| 0.3.x | 0.5.x |
| 0.4.x | 0.6.x |

Upgrade the application's native provider and adapter together. The default
`escope-lvgl` library and custom `TreeSource` implementations remain independent
of LVGL. Existing protocol-v1 devices can use this CLI and Inspector without a
firmware update. Rust UI migration details are available in the
[rs_lvgl 0.6 migration guide](https://umbrella22.github.io/rs_lvgl_website/guide/ui-api-migration.html).

## Downloads

| Platform | Inspector | CLI |
| --- | --- | --- |
| macOS Apple Silicon | `embedscope-inspector-0.4.0-aarch64-apple-darwin.zip` | `escope-0.4.0-aarch64-apple-darwin.zip` |
| macOS Intel | `embedscope-inspector-0.4.0-x86_64-apple-darwin.zip` | `escope-0.4.0-x86_64-apple-darwin.zip` |
| Linux x64 | `embedscope-inspector-0.4.0-x86_64-unknown-linux-gnu.AppImage` | `escope-0.4.0-x86_64-unknown-linux-gnu.zip` |
| Windows x64 | `embedscope-inspector-0.4.0-x86_64-pc-windows-msvc.zip` | `escope-0.4.0-x86_64-pc-windows-msvc.zip` |

- **Inspector:** extract the macOS or Windows ZIP and launch the application.
  On Linux, run `chmod +x` on the AppImage and start it.
- **CLI:** extract the ZIP and run `escope --help` (`escope.exe` on Windows).
  Add its directory to `PATH` for use from any terminal. Rust is not required.
- **C/C++ SDK:** `embedscope-c-sdk-0.4.0.zip` contains `include/escope.h`,
  device SDK sources, a lockfile and a static-library wrapper. Build it for the
  firmware target and link the resulting library.
- **Rust SDKs:** `escope-protocol`, `escope-agent`, `escope-lvgl`, `escope-c-api`
  and `escope-host` are available on crates.io. Rust users can optionally install
  the CLI with `cargo install escope-cli --version '=0.4.0' --locked`.

`SHA256SUMS` covers the nine attached distribution archives. Rust crate archives
are distributed through crates.io.

macOS applications use ad hoc signatures and are not notarized. Linux requires
glibc 2.35 or newer, and Inspector requires a desktop OpenGL driver; the CLI uses
system `libudev`. AppImage extraction is available on systems without FUSE.
Windows executables use the static MSVC runtime.

The release workflow checks source archives, independent Rust and C consumers,
the real `rs_lvgl_ui` 0.6.0 memory display, CLI sessions and packaged Inspector
launches. The native UI consumer runs against extracted SDK archives before
publication and registry-only dependencies after publication, with exactly one
`rs_lvgl_sys` 0.6.0 provider in each dependency graph.
