EmbedScope 0.5.0 supports the published `rs_lvgl` and `rs_lvgl_ui` 0.7.0
native provider. The device wire protocol remains **v1** and the C ABI is unchanged.

[Documentation](https://umbrella22.github.io/EmbedScope_website/)

## Native LVGL integration

- `escope-lvgl/native` directly uses `rs_lvgl_sys` 0.7.0 and shares the
  application's single LVGL 9.6 provider. Classification follows the effective
  widget and layout configuration, including no-layout, Grid-only and Flex-only
  applications.
- The new `range_slider` appears as `slider`, `chart(ChartSpec)` as one `chart`,
  and `custom(widget, props)` as its actual native class, such as `arc`. View
  keys, chart series IDs and custom Props do not add virtual nodes. Native
  widget internals remain visible; names require an application `TreeSource`.
- The independent 0.7 consumer checks controlled range/text events, authoritative
  text with editing filters, chart history and series retention, custom Props
  and lifecycle hooks, wrap/reverse geometry, native object reuse and stale tree
  revisions. Existing composition, overlay, real pointer input and RGB pixel
  checks continue to run.

## Upgrade

| EmbedScope native SDK | Shared `rs_lvgl_sys` provider |
| --- | --- |
| 0.1.x | 0.3.x |
| 0.2.x | 0.4.x |
| 0.3.x | 0.5.x |
| 0.4.x | 0.6.x |
| 0.5.x | 0.7.x |

Upgrade the application's provider and native adapter together and refresh its
lockfile. The default `escope-lvgl` library and custom `TreeSource` remain
independent of LVGL. Protocol-v1 devices can use the current CLI and Inspector
without updating firmware.

UI applications moving from 0.6 use `chart(ChartSpec)` with stable series IDs,
`CustomWidget::Props` and `custom(widget, props)`. Manually constructed Textarea
descriptions include the `input` field. Removed APIs have no compatibility
aliases. See the [rs_lvgl 0.7 migration guide](https://umbrella22.github.io/rs_lvgl_website/en/guide/ui-api-migration.html).

## Downloads

| Platform | Inspector | CLI |
| --- | --- | --- |
| macOS Apple Silicon | `embedscope-inspector-0.5.0-aarch64-apple-darwin.zip` | `escope-0.5.0-aarch64-apple-darwin.zip` |
| macOS Intel | `embedscope-inspector-0.5.0-x86_64-apple-darwin.zip` | `escope-0.5.0-x86_64-apple-darwin.zip` |
| Linux x64 | `embedscope-inspector-0.5.0-x86_64-unknown-linux-gnu.AppImage` | `escope-0.5.0-x86_64-unknown-linux-gnu.zip` |
| Windows x64 | `embedscope-inspector-0.5.0-x86_64-pc-windows-msvc.zip` | `escope-0.5.0-x86_64-pc-windows-msvc.zip` |

- **Inspector:** extract the macOS or Windows ZIP and launch the application.
  On Linux, make the AppImage executable and run it.
- **CLI:** extract the ZIP and run `escope --help` (`escope.exe` on Windows).
  Add its directory to `PATH` for use from any terminal. Rust is not required.
- **C/C++ SDK:** `embedscope-c-sdk-0.5.0.zip` contains the header, device SDK
  sources, a lockfile and a static-library wrapper for the firmware target.
- **Rust SDKs:** five libraries and `escope-cli` are available on crates.io.
  Rust users can optionally use `cargo install escope-cli --version '=0.5.0' --locked`.

`SHA256SUMS` covers the nine distribution archives. Rust `.crate` archives are
distributed through crates.io and retained as CI validation artifacts.

macOS applications use ad hoc signatures and are not notarized. Linux requires
glibc 2.35+, system `libudev` for CLI and a desktop OpenGL driver for Inspector.
AppImage extraction supports systems without FUSE. Windows uses the static MSVC
runtime.

The release workflow validates extracted SDK and C consumers, registry-only
consumers, native UI memory displays, CLI sessions and packaged Inspector
launches. Native consumers require exactly one registry `rs_lvgl_sys` 0.7.0.
Memory displays and hosted builds provide no physical-board acceptance.
