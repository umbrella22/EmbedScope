EmbedScope 0.2.0 improves native LVGL node inspection and navigation in the
desktop Inspector. The device wire protocol remains **v1**.

[Documentation](https://umbrella22.github.io/EmbedScope_website/)

## Native LVGL inspection

- `escope-lvgl/native` uses `rs_lvgl_sys` 0.4.0 directly, sharing the provider
  used by `rs_lvgl` and `rs_lvgl_ui` 0.4.0.
- `NativeTree` reports enabled widget kinds such as `label`, `button`, `slider`
  and `image`. Plain Flex/Grid objects appear as `row`, `column` or `grid`;
  other native objects appear as `lv_obj`.
- Classification follows the application's effective LVGL configuration,
  including builds with Flex or Grid disabled. A widget's class takes priority
  over its layout: a button with Flex remains a `button`.
- Native host objects and internal widget nodes remain visible. Names are
  empty; label text, View keys and component metadata can be supplied by an
  application-defined `TreeSource`.

## Inspector

- Object subtrees are displayed together in hierarchy order while preserving
  the provider's sibling order.
- Search results retain the matching nodes' ancestor paths.
- Inspect mode selects overlapping objects in reverse hierarchy paint order.

## Upgrade

Native integrations using `escope-lvgl` 0.2.0 require the matching
`rs_lvgl_sys` 0.4.0 provider and the application's actual LVGL configuration.
Applications using the 0.3 provider can retain SDK 0.1.x or upgrade their
provider together with the adapter. Do not link two native LVGL providers.

The default `escope-lvgl` library and custom `TreeSource` implementations remain
independent of LVGL. Existing protocol-v1 device integrations can use the new
CLI and Inspector without a firmware update.

## Downloads

| Platform | Inspector | CLI |
| --- | --- | --- |
| macOS Apple Silicon | `embedscope-inspector-0.2.0-aarch64-apple-darwin.zip` | `escope-0.2.0-aarch64-apple-darwin.zip` |
| macOS Intel | `embedscope-inspector-0.2.0-x86_64-apple-darwin.zip` | `escope-0.2.0-x86_64-apple-darwin.zip` |
| Linux x64 | `embedscope-inspector-0.2.0-x86_64-unknown-linux-gnu.AppImage` | `escope-0.2.0-x86_64-unknown-linux-gnu.zip` |
| Windows x64 | `embedscope-inspector-0.2.0-x86_64-pc-windows-msvc.zip` | `escope-0.2.0-x86_64-pc-windows-msvc.zip` |

- **Inspector:** extract the macOS or Windows ZIP and launch the application.
  On Linux, run `chmod +x` on the AppImage and start it.
- **CLI:** extract the ZIP and run `escope --help` (`escope.exe` on Windows).
  Add its directory to `PATH` for use from any terminal. Rust is not required.
- **C/C++ SDK:** `embedscope-c-sdk-0.2.0.zip` contains `include/escope.h`,
  device SDK sources, a lockfile and a static-library wrapper. Build it for the
  firmware target and link the resulting library.
- **Rust SDKs:** `escope-protocol`, `escope-agent`, `escope-lvgl`, `escope-c-api`
  and `escope-host` are available on crates.io. Rust users can optionally install
  the CLI with `cargo install escope-cli --version '=0.2.0' --locked`.

`SHA256SUMS` covers the nine attached distribution archives. Rust crate archives
are distributed through crates.io.

macOS applications use ad hoc signatures and are not notarized. Linux requires
glibc 2.35 or newer, and Inspector requires a desktop OpenGL driver; the CLI
uses system `libudev`. AppImage extraction is available on systems without
FUSE. Windows executables use the static MSVC runtime.

The release workflow tests source archives, independent Rust and C consumers,
a real `rs_lvgl_ui` memory display, CLI sessions and packaged Inspector launches.
The native UI consumer runs against extracted SDK archives before publication
and registry-only dependencies after publication.
